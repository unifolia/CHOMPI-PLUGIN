## Comments and docs

The reader is future Claude sessions: cut for tokens, not readability. Terse, not cryptic.

- Write only what the code can't say: the why, invariants, gotchas, measured numbers behind a choice or a rejection.
- Never restate the code, narrate history, or keep finished or abandoned plans here. Durable decisions live here, once.
- A comment that contradicts the code gets flagged to the owner, not deleted: the code may be what's wrong.
- Don't state an unmeasured performance claim as fact.
